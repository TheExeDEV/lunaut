# Editors

lunaut is a plain LSP server: `lunaut lsp` speaks JSON-RPC over stdio. VS Code has a full extension; every other editor only needs to start the binary.

| Editor | Folder | What to do |
| --- | --- | --- |
| VS Code | [`vscode/`](vscode) | Install the `lunaut.vsix` from a release (the installers do it for you) |
| Neovim 0.11+ | [`neovim/lunaut.lua`](neovim/lunaut.lua) | Copy into `~/.config/nvim/plugin/` or `require` it from your config |
| Helix | [`helix/languages.toml`](helix/languages.toml) | Merge into `~/.config/helix/languages.toml` (or `.helix/languages.toml` in a project) |
| Zed | [`zed/`](zed) | Install the **Luau** extension for highlighting and the **Lunaut** extension; it downloads the server from the latest release. Without the extension, merge [`zed/settings.json`](zed/settings.json) into Zed's settings to run lunaut in place of the luau-lsp binary |

## Settings outside VS Code

The server reads `.vscode/settings.json` in the project root by itself, so the same file works in every editor. Settings sent by the editor in `initializationOptions` win over the file. Use the flat VS Code form:

```json
{
	"vscode": {
		"lunaut.fflags.override": { "LuauSolverV2": "true" },
		"lunaut.rojo.projectFile": "default.project.json"
	}
}
```

`luau-lsp.*` keys work too; `lunaut.*` wins when both are set.

## What only VS Code has

- `rojo sourcemap --watch` runs inside the extension. Other editors get the sourcemap regenerated by the server on file changes (`lunaut.rojo.autogenerate`).
- The Studio companion plugin talks to an HTTP server hosted by the extension.
- Commands such as *Lunaut: Show FFlags* are VS Code UI; the same data is available through the [custom LSP methods](../README.md#custom-lsp-methods).
- Inserting `end` uses `workspace/applyEdit` outside VS Code, so the cursor stays where it was instead of jumping to the new line.
